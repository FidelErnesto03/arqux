# Projecting governance to every agent

*English translation — canonical source: `docs/es/guias/proyectar-agentes.md`*

ArqUX keeps **one source of truth** (`.arqux/` + the `AGENTS.md` template) and projects it to the files each harness reads natively. Two commands, one golden rule.

> **Golden rule:** projections are **regenerated, never hand-edited**. If you edit one, `drift-check` flags it as `DRIFT_DETECTED` and `sync-harnesses` overwrites it — your edit is lost. Always edit the source.

## The canonical flow

```text
1. Edit the source         →  .arqux/ , AGENTS.md , skills
2. Regenerate projections  →  arqux sync-harnesses
3. Verify drift            →  arqux drift-check   (optional, anytime)
```

## 1. `arqux sync-harnesses`

Generates the 4 projections from the packaged template, each with its management header:

```bash
$ arqux sync-harnesses
source_hash:3691d4f4f770d6d6
  wrote AGENTS.md
  wrote CLAUDE.md
  wrote GEMINI.md
  wrote .opencode/instructions.md
```

| Generated file | Read by | Content |
|---|---|---|
| `AGENTS.md` | Codex / tools following the AGENTS.md standard | Governance kernel + `arqux:managed` header |
| `CLAUDE.md` | Claude Code | Identical kernel, `target:CLAUDE.md` in header |
| `GEMINI.md` | Gemini CLI | Identical kernel, `target:GEMINI.md` |
| `.opencode/instructions.md` | OpenCode | Identical kernel, `target:.opencode/instructions.md` |

Each file opens with:

```html
<!-- arqux:managed — generated by `arqux sync-harnesses`; manual edits are detected by `arqux drift-check` -->
<!-- source_hash:3691d4f4f770d6d6 target:CLAUDE.md -->
```

`source_hash` is the hash of the rendered source: the 4 projections share the same hash because they derive from the same kernel — drift means the file on disk no longer matches the projection.

> The 4 files hold the **same kernel** — only the header `target` changes. Four files, one government.

## 2. `arqux drift-check`

Compares each projection on disk with what the generator would produce today:

```bash
$ arqux drift-check
OK AGENTS.md
OK GEMINI.md
OK .opencode/instructions.md
DRIFT_DETECTED CLAUDE.md (drift)
--- expected/CLAUDE.md
+++ actual/CLAUDE.md
@@ -118,3 +118,4 @@
 $6: DOGFOODING
 
 AXM:dogfood{ ... }
+## nota manual añadida
```

- Exit code `1` on drift (usable in pre-commit or CI), `0` when all is synced.
- Shows the unified diff of each drifted file — you see exactly what was hand-edited.

**Recovery:** `arqux sync-harnesses` rewrites the projection back to `OK`. The manual edit is lost — which is precisely the point: the source is `.arqux/`, not the projected file.

## If you hand-edited a projection

1. Copy your change to the source (the workspace `AGENTS.md` or the template itself in `.arqux/`).
2. `arqux sync-harnesses` — regenerates the 4.
3. `arqux drift-check` — confirms `OK` on all 4, exit `0`.

## When to regenerate

- After modifying `.arqux/` (identities, skills, policies)
- After upgrading ArqUX (the template may change between versions)
- Before a commit — projections ship versioned alongside the source

## Cheatsheet

| I want | Command |
|---|---|
| Project governance to all CLIs | `arqux sync-harnesses` |
| Check whether someone edited a projection | `arqux drift-check` |
| Change the governance | Edit source → `sync-harnesses` |
| Know what my CLI reads | `AGENTS.md` (standard), `CLAUDE.md` (Claude), `GEMINI.md` (Gemini), `.opencode/instructions.md` (OpenCode) |

> Each CLI's file conventions may vary between versions — verify where your harness expects its instructions file. What ArqUX generates is what you see in the table; where each CLI places it is its own convention.
