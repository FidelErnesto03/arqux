# Proyectar el gobierno a cada agente

ArqUX mantiene **una fuente de verdad** (`.arqux/` + la plantilla `AGENTS.md`) y la proyecta a los archivos que cada harness lee de forma nativa. Dos comandos, una regla de oro.

> **Regla de oro:** las proyecciones se **regeneran, nunca se editan a mano**. Si editas una, `drift-check` la marca como `DRIFT_DETECTED` y `sync-harnesses` la sobrescribe — tu edición se pierde. Edita siempre la fuente.

## El flujo canónico

```text
1. Editas la fuente        →  .arqux/ , AGENTS.md , skills
2. Regeneras proyecciones  →  arqux sync-harnesses
3. Verificas deriva        →  arqux drift-check   (opcional, en cualquier momento)
```

## 1. `arqux sync-harnesses`

Genera las 4 proyecciones desde la plantilla empaquetada, cada una con su cabecera de gestión:

```bash
$ arqux sync-harnesses
source_hash:3691d4f4f770d6d6
  wrote AGENTS.md
  wrote CLAUDE.md
  wrote GEMINI.md
  wrote .opencode/instructions.md
```

| Archivo generado | Lo lee | Contenido |
|---|---|---|
| `AGENTS.md` | Codex / herramientas que siguen el estándar AGENTS.md | Kernel de gobierno + cabecera `arqux:managed` |
| `CLAUDE.md` | Claude Code | Idéntico kernel, `target:CLAUDE.md` en cabecera |
| `GEMINI.md` | Gemini CLI | Idéntico kernel, `target:GEMINI.md` |
| `.opencode/instructions.md` | OpenCode | Idéntico kernel, `target:.opencode/instructions.md` |

Cada archivo abre con:

```html
<!-- arqux:managed — generated by `arqux sync-harnesses`; manual edits are detected by `arqux drift-check` -->
<!-- source_hash:3691d4f4f770d6d6 target:CLAUDE.md -->
```

`source_hash` es el hash de la fuente renderizada: las 4 proyecciones comparten el mismo hash porque derivan del mismo kernel — la deriva significa que el archivo en disco ya no coincide con la proyección.

> Los 4 archivos contienen el **mismo kernel** — solo cambia el `target` de la cabecera. Los 4 archivos, un solo gobierno.

## 2. `arqux drift-check`

Compara cada proyección en disco con lo que el generador produciría hoy:

```bash
$ arqux drift-check
OK AGENTS.md
OK GEMINI.md
OK .opencode/instructions.md
DRIFT_DETECTED CLAUDE.md (drift)
--- expected/CLAUDE.md
+++ actual/CLAUDE.md
@@ -118,3 +118,4 @@
 $6: DOGFOODING
 
 AXM:dogfood{ ... }
+## nota manual añadida
```

- Exit code `1` si hay deriva (usable en pre-commit o CI), `0` si todo está sincronizado.
- Muestra el diff unificado de cada archivo desviado — ves exactamente qué se editó a mano.

**Recuperación:** `arqux sync-harnesses` reescribe la proyección y la devuelve a `OK`. La edición manual se pierde — que es precisamente el punto: la fuente es `.arqux/`, no el archivo proyectado.

## Si editaste una proyección a mano

1. Copia tu cambio a la fuente (`AGENTS.md` del workspace o la plantilla propia en `.arqux/`).
2. `arqux sync-harnesses` — regenera las 4.
3. `arqux drift-check` — confirma `OK` en las 4, exit `0`.

## Cuándo regenerar

- Tras modificar `.arqux/` (identidades, skills, políticas)
- Tras actualizar ArqUX (la plantilla puede cambiar entre versiones)
- Antes de un commit — las proyecciones van versionadas junto a la fuente

## Cheatsheet

| Quiero | Comando |
|---|---|
| Proyectar el gobierno a todos los CLIs | `arqux sync-harnesses` |
| Ver si alguien editó una proyección | `arqux drift-check` |
| Cambiar el gobierno | Editar fuente → `sync-harnesses` |
| Saber qué lee mi CLI | `AGENTS.md` (estándar), `CLAUDE.md` (Claude), `GEMINI.md` (Gemini), `.opencode/instructions.md` (OpenCode) |

> Las convenciones de archivo de cada CLI pueden variar entre versiones — verifica dónde espera tu harness su archivo de instrucciones. Lo que ArqUX genera es lo que ves en la tabla; dónde lo coloca cada CLI es su convención.
