# ISSUE: DESIGN GAP — no native projection marks in ArqUX timelog. Real incident (ENVX_INFRA, 2026-10-21): a 372-min session was projected to Teamwork via tw_log (manual path), which wrote the remote timelog (id 18418907) but left NO local link — the LOCAL/teamwork ledger segment had to be inserted manually afterwards. REQUIREMENT: the native timelog must carry a projection-marks record inside the session timelog file itself (e.g. a PRJ section or marks appended per block in SESxxx_*.cortex — design decision open). Each mark should capture: provider/destination, remote_id (e.g. Teamwork timelog_id), projected interval (start/end/minutes — may DIFFER per provider: partial splits, different boundaries), projection date/agent, and a link back to the native block(s) it covers. One session may legitimately project N times to N providers, and even different hour ranges to different systems — so marks must be plural, per-provider, and never overwrite each other. Also required: timelog.project/manual bridges must write this mark atomically on send/reconcile, so 'already projected?' is answerable from the native file alone, without trusting external ledgers. Current workaround: provider-owned ledger (LOCAL/teamwork/ledger.sqlite) — provider ids live outside governance, which is correct per LIM:no_coupling, but the native file still needs its own provider-agnostic projection registry (store remote ids opaquely, no provider coupling in semantics).
